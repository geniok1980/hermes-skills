# Skill для чеков коррекции R-Keeper

## Описание

Этот skill позволяет парсить тексты чеков из системы R-Keeper и преобразовывать их в JSON формат для чеков коррекции.

## Использование

### Через агента

1. Скопируйте текст чека R-Keeper
2. Передайте его в opencode с запросом создать чек коррекции
3. Укажите параметры:
   - Тип коррекции: приход/расход/возврат
   - Система налогообложения: ОСН/УСН/ЕНВД/Патент
   - Тип оплаты: наличные/безналичные

## Формат входного чека

Чеки могут приходить в двух форматах.

### Табличный (стандартный печатный чек)

```
СЫРОВАРНЯ ВЕРНАДКА
1 Чек #483751      Стол 5
03.04.2026    Открыт 23:41  Закрыт 23:43

Кассир:   Сидорова Кристина
Официант: Куклина Анна

Блюдо                  Кол-во      Сумма
----------------------------------------
Паппарделле со           2,00    2900,00
шпинатом и креветками
Кьянти, Сан'Орсола      1,00     790,00
125мл
    DataMatrix/PDF417
...
----------------------------------------
Всего:                           9130,00
----------------------------------------
Нетмонет              9130,00    9130,00
```

### OCR-формат (разряженные цифры)

Каждая цифра на отдельной строке или через пробел. Характерен для PDF-скан-распознавания.

Подробнее — `references/ocr-spaced-format.md`.

```json
[

    "type": "sellCorrection",
    "taxationType": "usnIncome",
    "electronically": true,
    "ignoreNonFiscalPrintErrors": false,
    "correctionType": "self",
    "correctionBaseDate": "2026.04.03",
    "operator": {
      "name": "Сидорова Кристина",
      "vatin": ""
    },
    "clientInfo": {
      "emailOrPhone": ""
    },
    "items": [
      {
        "type": "position",
        "name": "Паппарделле со шпинатом и креветками",
        "price": 1450.0,
        "quantity": 2.0,
        "amount": 2900.0,
        "department": 1,

        "itemUnits": "piece",

          "type": "none"
        }

    "payments": [
      {
        "type": "cash",
        "sum": 9130.0
      }
    ],
    "total": 9130.0

```

## Параметры чека коррекции

### type — Тип коррекции

Обязательный. Определяет вид чека коррекции.

| Значение | Описание |
|----------|----------|
| `sellCorrection` | Чек коррекции прихода |
| `buyCorrection` | Чек коррекции расхода |
| `sellReturnCorrection` | Чек коррекции возврата прихода (ФФД ≥ 1.1) |
| `buyReturnCorrection` | Чек коррекции возврата расхода (ФФД ≥ 1.1) |

### payments[].type — Способ расчёта

Обязательный. Определяет форму оплаты.

| Значение | Числовой код | Описание |
|----------|-------------|----------|
| `cash` | `0` | Наличными |
| `electronically` | `1` | Безналичными |
| `prepaid` | `2` | Предварительная оплата (аванс) |
| `credit` | `3` | Последующая оплата (кредит) |
| `other` | `4` | Иная форма оплаты (встречное предоставление) |
| `5`-`9` | `5`-`9` | Пользовательский тип оплаты |

Оплата чека:
```json
{
    "type": "cash",
    "sum": 1000.00
}
```

Оплата чека с комментарием (безналичные):
```json
{
    "type": "electronically",
    "sum": 1000.00,
    "printItems": [
        {
            "type": "text",
            "text": "в т.ч. плат. карта онлайн = 1000.00 руб"
        }
    ]
}
```

### electronically — Признак электронной оплаты

Обязательный. Связывает `payments[].type` с полем верхнего уровня:

- `true` — если оплата безналичная (`electronically`/`1`-`9`)
- `false` — если оплата наличными (`cash`/`0`)

### tax — Налог

Обязательный. Указывается для каждой позиции (`items[].tax`) и для всего чека.

| Значение | Описание |
|----------|----------|
| `none` | Налогом не облагается |
| `vat0` | НДС 0% |
| `vat10` | НДС 10% |
| `vat110` | НДС 10/110 |
| `vat20` | НДС 20% |
| `vat120` | НДС 20/120 |
| `vat5` | НДС 5% |
| `vat105` | НДС 5/105 |
| `vat7` | НДС 7% |
| `vat107` | НДС 7/107 |
| `vat22` | НДС 22% |
| `vat122` | НДС 22/122 |

Пример:
```json
{
    "type": "vat20",
    "sum": 12.43
}
```

## Системы налогообложения

| Код | Описание |
|-----|----------|
| `osn` | Общая система |
| `usnIncome` | УСН (Доходы) |
| `usnIncomeOutcome` | УСН (Доходы минус Расходы) |
| `esn` | ЕСН |
| `patent` | Патентная |

## Примеры

### Пример 1: Чек коррекции прихода (УСН, наличные)

**Вход:** текст чека R-Keeper

**Параметры:**
- Тип: sellCorrection
- СНО: usnIncome
- Оплата: наличные (Нетмонет)

### Пример 2: Чек коррекции возврата прихода (ОСН, карта)

**Параметры:**
- Тип: sellReturnCorrection
- СНО: osn
- Оплата: карта

## Формат даты

Дата всегда должна иметь формат **YYYY.MM.DD** (например, 2026.04.02) — год, месяц, день. Это применяется ко всем полям `correctionBaseDate` и аналогичным.

## Особенности парсинга

1. **Многострочные названия** - объединяются в одну строку
2. **DataMatrix/PDF417** - строки игнорируются
3. **Итоговая сумма** - извлекается из строки "Всего:"
4. **OCR-формат** - если цифры разбиты пробелами/переносами строк, см. `references/ocr-spaced-format.md`
5. **Маркеры АТНМ/Товар** — атрибуты расчётного объекта для предыдущей позиции:
   - `Товар` → `paymentObject: "commodity"`
   - `АТНМ` → алкогольная продукция, также `paymentObject: "commodity"` (или `"excise"` для подакцизных товаров)
   - Строки `Полный расчет`/`Без НДС` после маркера — атрибуты той же позиции (paymentMethod и tax)
6. **Тип оплаты**:
   - "Наличными" → `cash`, `electronically: false`
   - "Нетмонет", "Карта", "Безнал" → `electronically`, `electronically: true`
